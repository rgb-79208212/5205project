# Evidence-Driven Deep Research 启动与使用说明

## 1 环境与目录

已验证环境为Windows、PowerShell和Python 3.12.7虚拟环境，建议使用Python 3.12复现；其他系统或更高版本需另行检查兼容性。检索模型在CPU运行，不要求GPU。模型准备、在线文献获取及DeepSeek调用需要网络。

以下命令均在`DSAI5205FinalProject-dmx2`根目录执行。本机可先进入：

```powershell
Set-Location 'F:\deskstop\DSAI5205FinalProject-main\DSAI5205FinalProject-dmx2'
```

项目位于其他位置时，替换上述路径。

## 2 启动

### 2.1 已配置环境

已有`.venv`、已准备模型并填写`.env`时，直接运行：

```powershell
.\.venv\Scripts\python.exe app.py
```

打开[研究页面](http://127.0.0.1:8776/research)。提交研究时，应用自动启动所需MCP服务，无须单独运行服务脚本。终端保持运行，按`Ctrl+C`停止服务。启动前已运行旧服务时，应停止后重新启动以加载当前代码。

### 2.2 首次安装

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare_models.py

if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

`prepare_models.py`下载公开Embedding与重排序权重，保存至`.models/`并验证推理。首次准备时间受网络影响；后续可复用缓存。该步骤无需额外API key。

编辑`.env`，填写本机密钥。以下为配置示例，值需替换：

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
LLM_API_KEY=your_deepseek_key
OPENALEX_API_KEY=your_openalex_key
```

`LLM_API_KEY`用于真实研究；建议填写[OpenAlex设置](https://openalex.org/settings/api)中的API key以减少匿名限流。已存在的`.env`应保留。公开模型准备、未受限公开数据集及百科工具无需另填密钥。完成后按2.1节启动。

### 2.3 更换端口与局域网访问

端口被占用时：

```powershell
.\.venv\Scripts\python.exe app.py --port 8777
```

访问`http://127.0.0.1:8777/research`。若需同一受信任局域网中的设备访问：

```powershell
.\.venv\Scripts\python.exe app.py --host 0.0.0.0 --port 8776
```

其他设备使用`http://运行电脑的局域网IP:8776/research`，并确保网络与防火墙允许该端口。局域网地址不等于公网发布地址。

## 3 提交研究问题

在输入框填写问题，点击**Research**。网页问题长度上限为500字符。建议给出完整论文标题、具体对象和比较维度；当前检索模型面向英文原文，英文问题更便于控制检索范围。

单篇论文查询示例：

> According to the original LoRA: Low-Rank Adaptation of Large Language Models paper, which weights remain frozen during adaptation? Answer only this factual point, without numerical benchmarks.

跨论文综合示例：

> In the original Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks and REALM: Retrieval-Augmented Language Model Pre-Training papers, compare the training signal used to learn retrieval. First read each original, then synthesize the difference. Do not compare benchmark scores or claim that either method guarantees factual correctness.

系统自动规划和选择方法，不要求手动指定MCP工具。RAG使用该次研究取得的原文；六篇论文的检索诊断集不限制日常问题范围。复杂或过宽的问题可能只得到部分回答。

## 4 查看与理解结果

| 页面部分 | 操作与含义 |
|---|---|
| 执行进度 | 查看规划、读取、审查和整理过程 |
| Show MCP details | 展开工具调用、参数、耗时和结果状态 |
| 回答与摘要 | 阅读通过发布检查的结论 |
| 引用按钮与Evidence | 查看引文、来源、位置、访问级别、版本哈希及关联结论；数量可能包含覆盖诊断，不等于文献篇数 |
| Coverage and withheld claims | 查看验收项、证据缺口及被扣留结论的原因 |
| 表格与覆盖图 | 查看结论和证据对应关系；覆盖图不是模型性能排名 |
| Methodology / Limitations | 查看处理方式、停止原因与未解决内容 |
| Export PDF | 通过浏览器打印或另存当前回答为PDF |

结果状态应分别解读：

| 任务状态 | 含义 |
|---|---|
| `complete` | 系统验收项满足，存在可发布结论 |
| `partial` | 已有可发布结论，仍有未满足要求 |
| `sources_only` | 已登记原文证据，尚无可发布结论 |
| `no_evidence` | 尚无有效登记的实质证据 |

执行情况另有正常完成、带警告完成、预算受限或失败。`complete`与“检查通过”均不构成人工正确性保证；需要核对重要结论的原文及适用条件。

## 5 配置调整

在`.env`中修改后重新启动网页服务。未填写的配置使用代码默认值。

| 配置 | 默认值 | 用途 |
|---|---|---|
| `RETRIEVAL_MODE` | `hybrid-no-rerank` | BM25与语义融合，不重排 |
| `RESEARCH_PARALLELISM` | `2` | 阅读分支并行数，支持1或2 |
| `MAX_ROUNDS` | `3` | 分支研究轮数上限 |
| `MAX_TOOL_CALLS` | `36` | 研究动作预算，包含取段落和登记引文 |
| `RESEARCH_TIMEOUT` | `240` | 总体研究时间预算，单位为秒 |
| `MODEL_TIMEOUT` | `40` | 单次模型请求超时，单位为秒 |
| `RESEARCH_ENGINE` | `graph` | 网页默认使用任务图；`linear`用于流程对照 |
| `RESEARCH_METHODS` | `enabled` | 启用任务型方法包；`disabled`用于对照 |

检索模式还可设为`lexical`、`bm25`、`dense`或`hybrid`。`hybrid`启用TinyBERT重排序，应先完成模型准备；本次诊断未显示重排收益。Embedding不可用时会记录降级为BM25，重排失败时会记录降级为不重排的融合配置。

复杂问题在分支与综合之间分配预算，Host自动登记候选、交接证据的协议请求另行记录。增加预算不保证完成，也不等于准确率提高。

## 6 命令行与恢复

命令行研究入口：

```powershell
.\.venv\Scripts\python.exe research_cli.py "研究问题"
```

输出事件记录及研究编号。需要限制为一路执行时，增加`--parallelism 1`。该命令行入口固定使用任务图；网页的`RESEARCH_ENGINE`对照配置不改变其执行器。

继续未完成的任务图：

```powershell
.\.venv\Scripts\python.exe research_cli.py --resume "研究编号"
```

恢复沿用原问题，保留已完成分支，重试未完成工作；恢复前状态存入`graph-history/`，各次分支尝试存入`branches/`。只有保存任务图的运行支持恢复。新问题应启动新研究，不应修改恢复任务的原问题。

## 7 文件、迁移与复现

| 路径 | 内容 |
|---|---|
| `.env` | 本机密钥与运行配置 |
| `.models/` | 检索权重、模型准备记录和向量缓存 |
| `runs/研究编号/research-state.json` | 原始问题、任务图、候选结论、审查、缺口和结果 |
| `runs/研究编号/tool-state.json` | 来源、原文版本与登记证据 |
| `runs/研究编号/branches/` | 分支状态和历次尝试 |
| `.planning/architecture-upgrade/` | 阶段记录、验收日志、对照结果与源码快照 |

换机时复制源码、`core/`、`skills/`、`web/`、`evaluation/`、`tests/`、依赖文件、`mcp_servers.json`、README及完整`report-docs/`，重新安装环境和准备模型。`report-docs/figures/`为正文插图，应与三个文档一并保留。核对历史结果时，可另保留`.planning/`中的报告、JSON和文本日志；无需复制其中的临时环境或`.venv`。密钥在新机器单独配置。

本地回归不调用云模型：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

检索对照不调用云语言模型，首次可能下载公开论文：

```powershell
.\.venv\Scripts\python.exe evaluation/architecture.py
```

对照结果默认保存至`.planning/architecture-upgrade/retrieval-ablation.json`。需要保留已有诊断时，可用`--output`指定新文件，例如`--output runs/retrieval-check.json`。真实研究及真实模型评估会产生提供商调用费用。

## 8 常见问题

| 现象 | 处理 |
|---|---|
| `python`不存在或指向不可用别名 | 安装Python 3.12，或使用本机有效Python路径建立环境 |
| 缺少依赖、模型加载报错 | 使用本目录`.venv`重新安装依赖，运行`prepare_models.py`；确认终端位于项目根目录 |
| 页面提示未配置模型或认证失败 | 检查`.env`中的密钥、服务地址与模型名，保存后重启 |
| OpenAlex限流或正文无法访问 | 检查key与网络；查看是否回退到其他来源，或缩小问题、稍后重试 |
| 检索出现降级警告 | 检查`.models/`与模型准备结果；结果中的实际配置优先于请求配置 |
| 任务部分完成或预算受限 | 查看缺口和扣留原因，缩小问题，或在保留原问题的前提下恢复任务 |
| 页面无法访问 | 确认终端服务仍运行，浏览器端口与启动参数一致 |

技术原理见[项目叙述](02_项目叙述.md)，修改及实测依据见[项目改进报告](01_改进报告.md)。
